# 高度な管理方法

## 設定ファイルで対話入力を省略する

ログイン情報や実行モードを JSON ファイルに書いておくと、対話式の入力を省略できます。

`scripts/launcher/inputs.example.json` を雛形に、リポジトリのルートへ `inputs.json` を保存してください。

```json
// inputs.json
{
  "workspace": "<workspace>",
  "email": "<email>",
  "password": "<password>",
  "mode": "update",
  "includeNsfw": false,
  "debug": false
}
```

登録スクリプトに設定ファイルのパスを渡すと、その内容で実行されます。

```bash
npm run launch -- inputs.json
```

パスは下記の順に探します。どのディレクトリで実行しても、リポジトリのルートに置いた `inputs.json` を指せます。

1. 絶対パス
2. 実行時のカレントディレクトリからの相対パス
3. リポジトリのルートからの相対パス

渡したパスにファイルが見つからない場合は、対話式には切り替わらずにエラーで終了します。

`inputs.json` と `inputs.*.json` は `.gitignore` に入っているので、パスワードを書いてもコミットされません。ワークスペースごとに `inputs.decomoji-dev.json` のように分けておくこともできます。

### 設定ファイルの型

| キー        | 値の型                                                             | 値の凡例             | 注記                                                                        |
| :---------- | :----------------------------------------------------------------- | :------------------- | :-------------------------------------------------------------------------- |
| workspace   | `string`                                                           | `"decomoji"`         | ワークスペースのサブドメインです。                                          |
| email       | `email`                                                            | `"otiext@gmail.com"` |                                                                             |
| password    | `string`                                                           | `"hogehoge"`         | `logs/` には保存されません。                                                |
| mode        | `"update" \| "uninstall" \| "migration" \| "compatible_migration"` | `"update"`           | 実行モードです。下記の対応表を参照してください。                            |
| includeNsfw | `boolean`                                                          | `false`              | 省略可。省略すると `false` です。露骨セットを扱うか否かです。               |
| debug       | `boolean`                                                          | `false`              | 省略可。省略すると `false` です。ブラウザを表示して開発者ツールを開きます。 |

`mode` の値と、対話式での表示の対応は下記の通りです。

| 値                     | 対話式での表示 |
| :--------------------- | :------------- |
| `update`               | 更新           |
| `uninstall`            | 全削除         |
| `migration`            | 移行           |
| `compatible_migration` | 互換のある移行 |

設定ファイルの内容は、ブラウザを起動する前に確かめます。`workspace`・`email`・`password` が空だったり、`includeNsfw`・`debug` に `"false"` のような文字列を書いていたりするとエラーで終了します。

## 露骨セットを扱う

露骨セット（`explicit` カテゴリー）はデフォルトでは**追加も削除もしません。**

扱う場合は `--include-nsfw` オプションを付けるか、設定ファイルに `"includeNsfw": true` を書いてください。どちらか一方が有効なら露骨セットを扱います。

```bash
npm run launch -- --include-nsfw
npm run launch -- inputs.json --include-nsfw
```

オプションは有効にすることしかできません。設定ファイルに `"includeNsfw": true` と書いてある時は、オプションを外しても露骨セットを扱います。

`--include-nsfw` 以外のオプションを渡すとエラーで終了します。

### あとから有効にした時

露骨セットを扱わずに更新を重ねてきたワークスペースで有効にすると、次の更新で露骨セットを全て追加します。

### 全削除する時

全削除も `includeNsfw` に従います。露骨セットを入れているワークスペースで全て削除する場合は、`--include-nsfw` を付けて実行してください。

## 実行結果のログ

実行するたびに、結果を `logs/` に保存します。

| ファイル                       | 内容                                               |
| :----------------------------- | :------------------------------------------------- |
| `logs/history.json`            | 最新の実行結果。次回の「更新」の基準になります。   |
| `logs/history_<実行日時>.json` | 実行ごとの結果。新しいものから 30 件まで残します。 |

`logs/history.json` には主に下記を記録しています。

| キー         | 内容                                                                                   |
| :----------- | :------------------------------------------------------------------------------------- |
| `version`    | ワークスペースに入れ終えたデコモジセットのバージョン。全削除すると `null` に戻ります。 |
| `compatible` | v5 の名前のエイリアスを貼って運用しているワークスペースか否か。                        |
| `inputs`     | 実行時の入力。パスワードは含みません。                                                 |
| `results`    | 追加・削除・エイリアス登録それぞれの成功と失敗の一覧。                                 |

`logs/history.json` を消すと次の「更新」は初回の実行として扱われ、v6 を全て追加しにいきます。登録済みのものはスキップされますが、修正されたデコモジの差し替えは行われません。

### 更新は history.json を引き継ぐ

「更新」は前回の `version` との差分を処理します。

- 前回より後に追加されたデコモジを追加する
- 前回より後に修正されたデコモジを削除してから追加し直す
- 前回より後に配布をやめたデコモジを削除する
- 互換のある移行をしたワークスペースでは、上記で追加したデコモジにエイリアスを貼る（貼り直す）

`compatible` も前回の値を引き継ぐので、互換のある移行をした後は「更新」を重ねてもエイリアスが維持されます。

## 失敗した時

途中で失敗すると、後続の処理（例えば削除に失敗した後の追加）は行わずに終了します。終了コードは `1` です。

その場合も `logs/history.json` にはそこまでの結果が残りますが、`version` は進めません。原因を取り除いてから、同じモードでもう一度実行してください。登録済みのデコモジはスキップされ、入れ損ねたぶんが処理されます。

## 既知の振る舞い

- **全削除の後に「更新」をしてもエイリアスは戻りません。** 全削除で `compatible` が `false` に戻るためです。エイリアスも戻したい場合は「互換のある移行」を実行してください。
- **`includeNsfw` を有効・無効と何度も切り替えると、露骨セットを送り直すことがあります。** 登録済みのものはスキップされるので、ワークスペースへの影響はありません。
